# 本机整库备份与恢复

版本：0.2.2-local。用于本机管理员维护，含双方私人记录和密码哈希；普通个人留存请用设置中的“导出我的数据”。工具没有 HTTP 接口，不上传云端，不覆写现有数据库。

## 创建一致备份

在项目根目录执行：

```sh
node scripts/local-data.mjs backup
```

默认从 `.local/between-answers.sqlite` 创建新目录 `.local/backups/backup-时间-随机值/`，完成后打印路径。也可 `pnpm local:backup`。如果使用了自定义 `BETWEEN_ANSWERS_DB`，会以该文件为源；可用 `--db "文件路径"` 明确指定，用 `--out "备份父目录"` 选择存放位置。

可以在本地服务运行时执行。工具用 SQLite 备份接口捕获一致快照，包含 WAL 中已提交的数据，不包含未提交的修改；生成独立的 `data.sqlite`，不需要另拷 WAL。不会创建缺失的源库，也不复用或覆盖先前的备份目录。

一个有效备份目录包含：

- `data.sqlite`：双方账号哈希、私人记录、版本、共享、留言等完整数据。
- `manifest.json`：格式版本、应用/数据库版本、生成时间、文件大小及 SHA-256 摘要，不含答案或凭证正文。

清单最后写入；没有清单的中断产物不是有效备份。备份前后均检查结构、SQLite 完整性与外键引用。不要只复制正在运行的主数据库而遗漏 WAL。

## 验证与保管

```sh
node scripts/local-data.mjs verify ".local/backups/上一步打印的目录名"
```

可把整个备份目录复制到自己控制的另一块磁盘，再在复制后运行校验。存于同一硬盘的备份不能抵御该硬盘损坏；工具不自动删除旧备份，也没有收费存储或定时任务。

摘要用于发现意外损坏，不证明备份来源可信。只使用自己生成、可信保管的备份。备份不加密，访问权限依赖本机账户及存放位置；不要上传公开仓库或交给不应访问双方数据的人。默认路径在 Git 忽略范围内，数据库文件也全局忽略。

## 准备恢复副本

在交互终端运行：

```sh
node scripts/local-data.mjs restore ".local/backups/上一步打印的目录名"
```

工具为备份中仍存在的 A、B 账号分别提示新密码和确认输入，均不回显；至少 12 字符，不能与该账号在备份中的旧密码相同。不要把密码放进命令参数、环境变量或聊天。没有交互终端、密码不完整或确认不一致时不恢复。Ctrl+C 可取消。

恢复只新建 `.local/restored/recovery-时间-随机值/data.sqlite`；可用 `--out "父目录"` 改变存放位置。原库和备份都不修改，不会自动启动服务或切换用户正在使用的库。

只有权限清理、密码重设和完整性校验都完成后，才发布最终 `data.sqlite`。异常中断若留下 `pending.sqlite`，不要用它启动应用；重新执行恢复，使用成功时打印的新路径。

恢复副本中保留双方个人答案、笔记、历史版本、本人共享快照和留言，但关闭全部旧空间及共享，清空会话、邀请码和登录失败计数，更新密码哈希。原因是旧备份不能证明双方现在仍同意共享，也不应恢复旧会话和旧密码。恢复后各自重新登录；需要继续共同答题时重新绑定。已删除的内容可能仍存在于删除之前生成的整库备份，工具不会替用户销毁历史副本。

## 检查并选用副本

先核对恢复输出路径与备份日期。由本机管理员停止现有本地服务后，在新的 PowerShell 窗口指定恢复库启动：

```powershell
$env:BETWEEN_ANSWERS_DB = '恢复步骤打印的完整 data.sqlite 路径'
node scripts/local-dev.mjs
```

打开 http://127.0.0.1:5173 ，用新密码分别登录，核对自己的答案、笔记、版本和导出，确认旧共享不可读。原数据库文件仍保留；核对前不要删除它，也不要用恢复副本覆盖原文件。该环境变量只影响当前终端及其子进程；回到默认库时停止服务，在新终端按原启动步骤运行即可。

恢复是时间点还原，备份之后的新记录不在其中。先核对和导出所需内容，再由用户决定今后使用哪个库；当前不自动合并两个时间点的记录，不提供 JSON 导入。

## 已验证边界

自动化测试使用临时库和合成答案，覆盖服务运行中的 WAL、未提交事务、损坏文件、错误结构/版本/外键、非法清单路径、弱/缺失/复用密码、源库保留和恢复后的真实 API 权限。Windows 终端已用合成账号实际检查不回显输入。没有为测试读取或复制用户正在使用的私人数据库。

工具使用 Node.js 24 自带的 SQLite 和 crypto，没有新增运行依赖。原理参考 [Node SQLite 备份接口](https://nodejs.org/docs/latest-v24.x/api/sqlite.html#sqlitebackupsourcedb-path-options)；恢复工具只支持当前数据库结构版本 1，未知版本直接拒绝，不尝试修复或迁移损坏数据库。
