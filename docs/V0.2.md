# V0.2：渐进式工作台

沿用原生 HTML / CSS / ES Modules、静态构建和 GitHub Pages 发布链路，无新增运行依赖和后端。

## 使用

- 健康、投资、学习及首页的记录卡片支持编辑、确认删除；主题内可搜索全文，「全部记录」可跨主题搜索。
- 项目中心记录名称、状态、问题、成果、相关链接和下一步。应用中心保存已有应用外链，不嵌入或重做应用功能。应用列表初始为空，由用户填写真实地址。
- 首页只保存一个优先事项；继续上次进度保存最近访问的主题、项目、应用或原则阅读页及滚动位置。新模块通过手机侧边菜单进入，底部保留原来的四个快捷入口。
- 数据管理选择文件后先校验并列出模块，再确认导入。默认合并记录、项目、应用；同 ID 内容冲突时保留双方。每日勾选取较新日期，同日合并；优先事项、进度和主题保留当前值。账本同月份冲突时中止整次导入，需核对后选择替换或恢复。
- 「替换」只替换文件包含的模块，且会再次确认。「恢复到独立副本」可用于原数据损坏的情况；「恢复最近一次导入前快照」恢复快照中可读取的模块。文件缺少的模块保持当前状态。

## 数据约定

保留 `zhongtai.records.v1`、`zhongtai.daily.v1`、`fuli-monthly-assets-v1`、`zhongtai.theme` 原键。记录只修改指定条目，保留未知字段、旧分类、创建时间；不自动迁移或清空旧数据。记录采用原条目比对定位，兼容缺少 ID 的旧条目；完全相同的重复条目拒绝修改，避免误操作。

新增 `zhongtai.projects.v2`、`zhongtai.apps.v2`、`zhongtai.focus.v2`、`zhongtai.progress.v2`。新模块分别放在 `src/modules/centers/`、`data/`、`records/` 和 `overview/focus.js`。存储、备份校验和模块数据行为放在 `src/data/`，不依赖 DOM。

JSON 备份格式为 `{format:"zhongtai-backup",version:2,exportedAt,data,issues,raw}`。`data` 是通过校验的存储键到原始字符串的映射；`raw` 包含原始值、恢复副本和本地快照，便于保留损坏内容。导入只使用白名单内且通过校验的 `data`，不会执行或直接写入 `raw`。不支持猜测转换任意 JSON；损坏模块会列入 `issues`，只保留原文。

导入先完整校验与计算，再保存一份导入前快照到 `zhongtai.backup.v2`。所有目标值先暂存为独立 `zhongtai.copy.*` 键，最后通过一次 `zhongtai.active.v2` 索引写入切换。暂存或索引写入失败时原活动数据保持有效；暂存失败会清理本次已暂存的副本。已成功切换的旧副本保留，可能增加本地空间使用量。

普通写入和导入遇到格式损坏时中止。恢复会将有效文件写到独立副本并切换索引，原始损坏值保持逐字不变。索引或已有本地快照本身损坏时也拒绝覆盖，应先导出原始数据再排查。数据只在当前浏览器处理，不跨设备同步。浏览器清理站点数据会删除本地副本和快照，应定期导出文件。

## 验证

```powershell
node scripts/check.mjs
node scripts/build.mjs
node scripts/serve.mjs
# 另一个终端；Playwright 使用现有环境，不进入运行依赖
$env:PLAYWRIGHT_MODULE = '现有 Playwright 安装的 index.mjs 绝对路径'
node scripts/browser-check.mjs
node scripts/browser-v02.mjs
node scripts/check-motion.mjs
```

`check.mjs` 包含 V0.2 单元验证：记录编辑删除、旧字段保留、过期条目保护、全文搜索、链接安全、备份往返、合并冲突、配额失败和隔离恢复。

浏览器验证覆盖既有阅读和记录、V0.2 主要操作、文件下载和导入、原始损坏值保留、阅读滚动恢复、深色主题、手机导航及 320 / 390 / 768 / 1024 宽度。截图位于忽略的 `qa-output/`。所有测试数据均为虚构内容；私人备份放在忽略的 `private-data/` 或仓库外，勿提交私人数据。
