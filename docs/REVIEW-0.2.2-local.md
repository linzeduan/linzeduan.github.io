# 0.2.2-local 本地备份与恢复验收

2026-10-17。继续本地 V1 的可靠性工作，云端配置仍后置。

## 交付

- 独立本机管理员 CLI：`backup`、`verify`、`restore`，以及对应 pnpm 命令。没有新增 HTTP 接口、运行依赖或数据库表。
- SQLite 一致备份，读取已提交 WAL；每次新建目录，生成独立数据库、最后写入的清单和 SHA-256 摘要。源文件必须存在，禁止把错误路径当成空数据库新建。
- 结构、版本、完整性、外键、大小与摘要校验；拒绝非法清单数据库路径、损坏或不兼容的备份。
- 恢复只准备新副本，不改原库或备份。关闭旧共享，清空会话及邀请码，交互设置新密码，避免旧授权与旧凭据随备份恢复。保留双方各自的答案、笔记、版本和留言。
- 使用待完成文件，清理权限、更新密码及验证完成后才发布最终 data.sqlite，失败或取消不声称成功。
- 新增 LOCAL_BACKUP.md；更新本地使用说明与架构文档。

## 验证

`node scripts/check.mjs`：400 题原文校验、严格前端/探针/服务端类型检查、50 项单元与 HTTP 测试、构建通过；发布前对最终恢复逻辑又运行了相关 8 项测试并通过。

新增 8 项测试使用临时库和合成数据，覆盖：

1. 服务连接保持开启、WAL 尚未自动合并时创建完整独立备份；多次备份不覆盖旧文件。
2. 未提交事务不会进入备份。
3. 外键损坏拒绝备份。
4. 恢复副本保留个人数据和版本，原库的后续撤回不被改写；真实 API 验证旧会话/旧密码失效，新密码可登录，对方旧答案不可读。
5. 源路径缺失时不创建假空库。
6. 文件损坏与路径穿越清单拒绝恢复。
7. 未知结构/版本、弱密码、缺失密码和复用旧密码拒绝恢复，不改原库。
8. CLI 创建/校验不输出答案或凭据，非交互终端拒绝接收恢复密码。

Windows ConPTY 实际以合成账号完成四次新密码输入和恢复，输入没有回显；检查了副本中的新密码与合成记录，随后清理本次生成的测试目录。没有为演练读取、复制或重启用户正在使用的数据库和预览。

页面及服务 API 没有行为修改；本次本地验证集中于备份工具与恢复权限，GitHub CI 仍运行完整演示和本地浏览器回归。

## 边界与后续

整库备份仅供双方信任的本机管理员，包含双方私人数据与密码哈希，不是个人 JSON 导出，也不加密。保存在同一硬盘不能抵御硬盘损坏；摘要不能证明来源可信。只使用可信备份，另盘保管由用户自行选择。

恢复不会自动合并备份后的新记录，不提供 JSON 导入，不自动替换当前数据库。选用恢复副本前由用户核对时间与个人记录；需要继续共同答题时重新绑定。

本地版本的备份恢复已有可运行流程和证据。生产认证、双方真实网络直连、云端恢复与真机 PWA 仍未验收，完整项目继续保留这些门槛，不宣称正式 V1 已上线。
