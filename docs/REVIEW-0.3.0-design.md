# 0.3.0-design 产品交接验收

2026-10-17。按用户更新后的分工，完成产品设计和可运行资源交接，Work Buddy 使用已有域名、云数据库接入及上传。本轮没有创建或部署新云资源。

## 产品完成项

PRODUCT_DESIGN.md 汇总产品原则、信息架构、页面流转、加载/锁定/解锁/失联/冲突/撤回等状态、视觉规则与 V2 概念边界。19 张桌面/手机、浅深色预览全部使用合成内容。普通设置页移除平台探针入口；开发工具通过独立路由及文档保留。

收口中修正：

- 默认每日题进入后固定问题/轮次，跨过上海零点不换走编辑页；用户可主动打开今日题，页脚使用服务端的题目日期。
- 推荐日程结束后提供自由题/补答入口，不把旧题当作新题或声称已经答完。
- 私人回答可原子复制为共同题的新草稿，原记录保留，笔记始终私密；重试复用轮次 UUID。撤回后重新分享只开新轮，旧授权保持关闭。
- 校验题目/记录/轮次引用，错误链接不显示另一题的编辑器；历史读取失败提供重试。

## 验证证据

- `node scripts/check.mjs`：400 原题校验、严格前端/服务端/探针 TS、64 项单元与 HTTP 测试、构建通过。
- `playwright test`：16 项演示/PWA/原网络探针浏览器回归通过。
- `playwright test --config playwright.local.config.ts`：12 项桌面与手机尺寸测试通过，覆盖既有 V1 闭环，以及真实服务下的跨日继续编辑、日程结束、私人复制邀请、旧共享不可复活、错误链接和历史重试。
- 跨日测试只在私有临时目录注入测试时钟，不向生产入口加入改时能力；现有用户库和预览未被用于测试。
- `scripts/capture-design.mjs` 使用独立纯演示进程，生成 19 张预览，检查横向溢出；捕获后停止自己启动的服务。认证和跨日图片来自合成账号测试。人工检查了手机今日、编辑、交集、跨日和桌面深色设置。

## 交付物与边界

API_CONTRACT.md、HANDOFF_WORK_BUDDY.md 和 V1_ACCEPTANCE.md 明确云适配、身份、权限、事务、部署与真机验收。已有本机备份/导出文档继续保留。

`scripts/package-handoff.mjs` 仅从干净提交归档源码，以演示模式生成静态预览，记录版本与提交，并排除私人目录、数据库、原 DOCX 和真实凭证。交接包保存在被 Git 忽略的 .local/handoff；包中的演示资源不能冒充私人云服务。

本轮验收对象是产品设计、参考实现、资源和交接，不包含 Work Buddy 后续的域名/数据库实际部署。正式私人使用前仍由接入方运行云权限、跨设备同步、两人真实网络、真机 PWA 和云恢复验收。
